> 消费者服务专员每周要把公开投诉分给质量、活动或电商团队。难点在于一条投诉常混着几个问题，写到食用后症状的信号可能随活动投诉流走。我用黑猫投诉公开列表上该品牌一个产品系列的 {{n}} 条投诉（2026-07-15 至 10-15）比较关键词规则与 AI：规则在质量安全上 0 漏判，但把 {{o_ref}} 条订单发货中的 {{o_to_a}} 条错分进活动；AI 能区分这类词义重叠，并给出可逐字核对的原文依据。按每周约 {{weekly_round}} 条的量，单独做净价值为负，盈亏平衡约每周 {{breakeven}} 条。建议：规则兜底高风险条目，AI 等量上来后作为现有智能体平台的附加能力试点。企业事实均标注来源与证据类型；研究只用公开资料，内部流程列在第七节待访谈确认。

# 一、业务背景

**对本场景意味着什么？**

# 二、小痛点：一个人、一个时刻、一个任务

**选题调整。** 默认候选是“整理某款奶粉的电商差评”。核验时发现，京东、天猫的评价不登录拿不到，我不绕过登录墙。黑猫投诉上该品牌商家页的公开列表不需要登录，可以追溯到每一条投诉单号。所以改用同等规模的替代场景：把输入从“电商差评”换成“公开投诉平台上某一系列的投诉”。产品、任务和流程都不变。

| 要素 | 内容 |
|---|---|
| 使用者 | 消费者服务部负责公开投诉平台的专员（只服务一个产品系列） |
| 触发时刻 | 每周一上午，整理上周新增的公开投诉 |
| 输入 | 投诉标题与摘要（摘要常被平台截断）、投诉要求、单号 |
| 交付 | 一份核查清单：每条的类别、原文依据、是否需要人工优先核查，按责任方分派 |
| 推测的现有做法 | 逐条阅读，凭经验判断交给谁，手抄进表格（待访谈确认） |

**难点在哪？** 这 {{n}} 条样本折合每周约 {{weekly_round}} 条，整理本身不费时；难在两点：

- **分类不一致**：一条投诉常同时写着异物、客服推诿和十倍赔偿，该交给质量、客服还是电商运营，不同的人判断不同。
- **重要信号被埋住**：单号 17400228971 标题是“骗人的”，主要抱怨扫码活动，却写了“孩子吃了拉肚子”。这类信号跟着活动投诉走，就进不了质量核查。

**现有办法缺什么？** Excel 只能记录、不能判断；关键词规则遇到词义重叠会出错，比如“不发货”发的是奶粉还是赠品（第五节实测）；已知的客服质检只覆盖电话和 IM。**AI 负责其中一步**：读一条投诉，判断主要问题，摘出原文依据。

**待验证的业务假设：** 公开投诉有专人定期处理；分派给三方时存在口径不一或延误；症状描述可能随非质量类投诉流失。

**最关键的三个访谈问题：**

1. 黑猫这类公开投诉现在由谁看、多久看一次，和 400 及在线客服工单是不是同一个系统？
2. 一条公开投诉从被发现到交到质量、活动或电商团队手里，现在怎么流转？哪一步最常出错或拖延？
3. 集罐、买赠类问题，客服有没有统一的口径库？“线上线下不累计”这类问题，是规则设计如此，还是系统限制？

**范围压缩。** 时间预算 3–5 天，只验证一个假设：AI 能否比关键词规则更稳定地把公开投诉分到责任方，并给出可以核验的依据。

- 做：导入、分类与依据、人工修改、导出清单。
- 不做：自动回复、情感打分、多平台抓取、对接工单系统、异物成分判断、趋势预测、登录与权限。

# 四、产品方案

**一条完整流程（一个专员，每周一）：** 导入上周新增投诉 → AI 给出类别、原文依据和复核标记 → 专员确认或修改 → 导出核查清单 → 按类别交给质量部门、活动运营或电商运营。

**AI 只做一件事。** 输入一条投诉，输出类别（五选一，含“其他”“信息不足”）、逐字原文依据（≤40 字）、是否写到食用后症状、是否需复核及理由、原文中的批次号。不补全未写的信息，不判断责任和异物成分，不给喂养或医疗建议；质量安全和写到症状的条目一律需复核。

![演示页：筛选“质量安全”后，每条都附有黄色划线标出的原文依据（离线演示）](outputs/img/demo.png){width=82%}

演示页 `demo/投诉分拣演示.html` 双击即可打开：导入或粘贴 → 查看分类与依据 → 人工修改 → 导出 CSV 核查清单。页面标明“离线演示”：示例数据显示 Claude 预生成的结果，新粘贴的文本只走关键词规则（标“规则·非 AI”，一律需复核）。

**主要成功指标：“一次派对率”。** 定义：当周新增公开投诉中，专员复核时没有改类、并且附有原文依据的条目占比。它衡量投诉能否一次交到正确的人手里。

质量约束：质量安全和写到症状的条目漏标为 0（以人工复核为准）；依据与原文逐字一致率 100%；从发布到进入清单不超过 1 个工作日（试点实测）。

**规则错在哪：**

- {{o_ref}} 条订单发货中有 {{o_to_a}} 条被分进了活动，因为{{o_keywords}}先命中。例如“淘宝百亿补贴……超时不发货”命中了“补贴”。

**AI 正确的例子：** 赠品滑板车归为活动权益，依据“赠品滑板车存在质量缺陷，踏板内部鼓包凸起”；百亿补贴超时不发货归为订单发货，依据“下单时卖家承诺7月16日发货，截止至今卖家仍然不发货”。

{{ai_disagree_block}}**难判断的例子：** 17400228971 同时写了活动、发货和孩子拉肚子，AI 归为活动权益，但标出症状并要求复核（“有身体症状且多问题并存”），没有漏掉信号。17402080517 AI 比参考标签多标了一次复核，偏保守，可以接受。

**AI 的增量在哪里：**

- 词义重叠时的语义区分（本样本中规则任一版本分错、AI 分对的有 {{sem_n}} 条）、每条都可以几秒钟核对的原文依据、复核理由。
- 高风险分流由规则承担：规则在质量安全上已经 0 漏判。
- 设计取舍：规则作为高风险兜底（命中质量或症状词就强制复核），AI 负责其余条目的分拣和摘录依据。

# 六、商业价值：先算小账

**谁用、谁付、谁受益：** 消费者服务部使用并承担维护工时和模型费用；受益的是专员（省时）、质量部门（安全线索更全）、活动运营（规则问题反馈）和电商运营（拒发线索）。

**形态：选“现有系统的附加能力”。** 在已有的统一 AI 应用平台（报道称已有 436 个智能体）上配一个智能体，或接入现有客服系统。量太小，不值得单独做工具，更不值得外部采购；平台已在，增量成本最低。

**小账**（周量为实测；时长与单价为假设，可在 Excel“成本测算”表修改）：

净价值 = 节省的人工处理成本 − 新增复核、模型及维护成本

# 附录 A：两分钟面试讲解稿

我做了一个奶粉品牌的小型 AI 案例，只解决一件事：把公开投诉平台上某一产品系列的新增投诉，分到质量安全、活动权益、订单发货三类，每条附上原文依据，并标出需要人工优先核查的条目。

先说为什么选它。年报显示该品牌线下客户收入占七成以上，但产品也在大型电商平台直营。公开报道里，该品牌的 AI 已经用在工厂设备运维和人事上，客服侧有电话和 IM 的智能质检；公开投诉和电商评价怎么处理，公开资料里没有写，这是我要通过访谈验证的假设。

数据上，我从黑猫投诉的公开页面采了三个月共 {{n}} 条，用 SQL 看出两件事：一是异物类有 {{yiwu_n}} 条独立投诉；二是活动权益类 {{act_n}} 条里有 {{rule_n}} 条其实是规则没讲清或系统限制，比如线上线下集罐不累计。后一点更该反馈给活动运营，因为问题出在规则本身。

然后我把 AI 和关键词规则放在一起比。规则在质量安全上一条没漏，但把 {{o_ref}} 条订单发货里的 {{o_to_a}} 条错分进了活动，因为“活动价”“补贴”这类词先命中；调换顺序修好 {{v2_fixed}} 条，又错了 {{v2_broken}} 条。AI 的增量在于语义区分和逐字依据，{{n}} 条的依据都能在原文里找到。{{appx_label}}

最后算账：按每周 {{weekly_round}} 条左右的量，净价值是负的，盈亏平衡大约在每周 {{breakeven}} 条。所以我的结论是：高风险分流用规则兜底；AI 等扩展到电商差评或工单、量上来之后，再作为现有智能体平台上的一个附加能力去试点。我最想通过访谈确认的是：现在公开投诉由谁在看、多久看一次、分派时哪一步最容易出错。
